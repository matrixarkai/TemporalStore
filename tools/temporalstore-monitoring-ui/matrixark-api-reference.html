MatrixArk

API And Schema Reference

Operations Console Agent Envelope

Boundary

Agents send simple evidence. MatrixArk always extracts. TemporalStore serves the internal model.

Public Caller Model

messages + scope + metadata + optional hook evidence
-> MatrixArk extraction
-> ContextPack returned to agent

Hidden Internal Model

  • ContextEvent, ContextEntity, ContextIndex
  • ContextNode, ContextChildRef, ContextSummary
  • ContextEmbedding, ContextCompressionEvent, ContextPackAudit

Public APIs

HTTP endpoints are the production contract; MCP tools mirror the same shapes for local and agent integrations.

POST /v1/context/ingest

Ingest one message, tool output, business event, or resource description.

{
  "messages": [{"role": "user", "content": "Alice approved the GPU request."}],
  "scope": {"user_id": "alice", "session_id": "thread-gpu", "team": "infra_team"},
  "metadata": {"source": "cursor"},
  "agent_hook": {"hook_type": "before_llm", "auto_captured": true}
}

POST /v1/context/retrieve

Return a token-budgeted ContextPack for a raw query.

{
  "query": "What GPU approvals are current?",
  "scope": {"session_id": "thread-gpu", "team": "infra_team"},
  "max_context_tokens": 10000,
  "hints": {"retrieval_timeout_ms": 5000}
}

POST /v1/context/feedback

Capture confirmations, corrections, accepted refs, rejected refs, and final answer feedback.

{
  "messages": [{"role": "user", "content": "Yes, that answer is correct."}],
  "context_pack_id": "pack-thread-gpu",
  "accepted_refs": [{"ref_type": "event", "ref_hash": 52001}]
}

Batch, Stream, Resource, Audit, Replay

  • /v1/context/batch_ingest: per-row success and errors
  • /v1/context/stream_ingest: stream, partition, offset, payload
  • /v1/context/resource: raw URI, type, parsed chunks, embeddings
  • /v1/context/audit/{pack}: selected, blocked, dropped refs
  • /v1/context/replay/{pack}: replayable evidence

Retrieval Timeout Budget

Use separate budgets for model planning and TemporalStore traversal.

End-to-End Retrieval

MATRIXARK_RETRIEVAL_TIMEOUT_MS sets the context retrieval budget. Unset, the MCP server allows 30000 ms; the Rust launcher supplies 20000 ms. It was 5000 ms until a cold-start retrieve was found to exceed it and lose the pack.

  • Includes query understanding and optional LLM extraction
  • Includes query embedding generation
  • Includes TemporalStore traversal, filtering, compression lookup, and packing
  • Can be overridden with hints.retrieval_timeout_ms or hints.context_retrieval_timeout_ms

Traversal Sub-Budget

TemporalStore tree traversal should usually target hundreds of milliseconds, not the full model budget.

  • Filter children by scope, metadata, and secondary indexes first
  • Score L0/L1 summary embeddings only after filters
  • Pass only the remaining retrieval budget into traversal
  • Keep provider-level timeouts for OSS/OpenAI model calls in production

Timeout Fallback

If the retrieval deadline is reached, MatrixArk returns a normal replayable ContextPack with only context already fetched.

  1. Current ContextEvent records
  2. L1 summaries
  3. Resource chunks
  4. Compressed cold-window summaries
  5. Empty pack if no safe context was fetched

Observability

Prometheus and replay must show where the cutoff happened.

matrixark_pipeline_stage_latency_ms{
  operation="retrieve",
  stage="hard_timeout",
  status="timeout"
}

ContextPackAudit.decision_notes:
"hard retrieval timeout at query_embedding after 5004.21 ms"

MCP Server

The MCP server lets Codex, Cursor-like products, Claude, and vertical agents call MatrixArk as a context provider.

Run Locally

python3 tools/matrixark_mcp_server.py \
  --storage-prefix matrixark:mcp

Tools

  • matrixark_ingest: messages, scope, metadata, hook, resource refs
  • matrixark_retrieve: query, scope, max context tokens
  • matrixark_feedback: feedback messages, pack id, accepted/rejected refs
  • matrixark_replay: context pack id
