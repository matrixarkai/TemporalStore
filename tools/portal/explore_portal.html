Add a memory

Writes one turn through POST /v1/ingest, the same path an agent hook uses. Useful for checking that extraction and encoding are working before you point a real workload at the deployment.

Without “extract immediately” the write is acknowledged and extraction runs in the background, which is how a production ingest behaves — it just means a retrieve issued a moment later may not see it yet.

Upload a document

Streams the file through POST /v1/ingest_file to the blob tier and ingests it in one call — the same path the SDK uses. For a whole directory, use Ingestion instead.

Uploaded one at a time so a failure stops at the file it failed on.
Retry re-sends the file from this browser, so it works only while this tab stays open — the bytes never existed on the server. A bulk import from a server directory is retryable after a restart; see Ingestion.

Run a mem0 operation

Every method of the mem0 API, listed by the name you call it by rather than by the URL that serves it. The request is shown before it is sent and the raw answer after, so this doubles as the worked example for writing the call yourself. The scope comes from the fields above.

Batch ingest

Many memories in one submission. Each line is one memory: plain text, or a JSON object to set a per-line user, agent, session or metadata. The batch runs on the SERVER as a tracked job — closing this tab does not stop it, and its failures are retryable from Ingestion exactly like a directory import.
