Mental Model

Logical layer

Models expose key/value, hash, feature/time-series, MatrixArk context, and other business views. Context models are just another set of TemporalStore models, not a separate storage engine.

Index layer

Index owns the in-memory slot_id -> SlotNode map and the durable index stream. It tracks object metadata, page references, dirty slots, zone metadata, TTL, and GC safety.

Page layer

PageStore writes durable page bytes into zone streams. OpLogger writes WAL/oplog records and can also temporarily hold page data when pages are still in the log.

Lifecycle layer

StorageManager is the background loop that moves data from hot memory/log state toward durable pages and reclaims stale space through GC and compaction.

Client/API
  -> Partition command executor
  -> ObjectManager/Model code
  -> OpLogger writes WAL records
  -> Index marks slot/object/page dirty
  -> StorageManager later dumps dirty slots/pages
  -> PageStore writes zone streams
  -> Index persists current page/object metadata
  -> GC/compaction reclaims stale pages and oplog ranges

Core Storage Data Structures

PageIndex

PageIndex is a packed 17-byte public-internal page reference. It is the C++ equivalent of the shared page address contract, but in current code it is compact and implementation-oriented.

FieldMeaning
object_id, model_id, page_idIdentify which object/model page the address belongs to inside a slot.
dirtyPage reference still needs dumping or index reconciliation.
page_in_logIf true, address points into the oplog. If false, it points into PageStore zone storage.
page_sizePage bytes. A value of zero means deleted/stale page.
addressEither oplog record id or encoded zone address, depending on page_in_log.

SlotNode

SlotNode is the compact per-slot index entry. It stores either a trivial single page/object inline or a pointer to a richer layout. Its flags track dirty state, loading state, memory residency, page deletion, and whether the page lives in the oplog.

Index

Index keeps the hot slot_map_, writes durable index logs, tracks zone metadata, exposes slot iterators, and mediates page reference changes through OnPageAppended and OnPageWillDelete.

Write Path

write command
  -> ObjectManager / model executor mutates object
  -> OpLogger::WriteKvLog / WritePage / WriteTtlLog / DeleteObject
  -> current_oplog_ accumulates storage::OpLog::LogItem
  -> Index::MarkSlot*Dirty records first dirty log and sequence
  -> OpLogger::Commit serializes current_oplog_ to stream
  -> staged page logs become PageIndex entries with page_in_log=true
  -> StorageManager::ReclaimOpLog later dumps dirty slots to PageStore
  -> SlotStore::DumpSlots writes pages
  -> Index::SetDumpedLogId advances safe oplog truncation watermark

The write path is log-first. Page data can initially live in the oplog, then later be rewritten to PageStore. This is why PageIndex.page_in_log is critical: it tells reads whether to call OpLogger::ReadPage or PageStore::ReadPage.

Important implementation detail: OpLogger::Commit writes one serialized storage::OpLog record to the stream and patches staged page metadata with the resulting log id, log size, and sequence.

Read Path

logical key / model / timestamp lookup
  -> model code maps logical key to slot/object/page refs
  -> Index/SlotNode locates PageIndex records
  -> SlotStore/ObjectManager load pages
  -> if page_in_log: OpLogger::ReadPage
  -> else: PageStore::ReadPage
  -> decode PageHeader + page bytes
  -> model decodes records and applies filters

PageStore::ReadPage and OpLogger::ReadPage have different physical sources but both return PageInfo. That gives upper layers one decoded page abstraction even when old data is still in the log.

For ContextEvent and ContextSummary, model-level filtering happens through feature/time-series style key ranges. The C++ context extension uses ingestion-time keys and timeline query ranges, then applies type/confidence/importance/ranking filters.

Zones, Streams, Blobs

PageStore durable storage is organized into zones. Each zone owns a stream. The index stores zone metadata as IndexLog::ZoneInfo and treats zone state transitions as durable index metadata.

CREATED zone
  -> accepts PageStore writes until stream length reaches storage_zone_size
  -> becomes FROZEN
  -> PageGc chooses low-utility frozen zones
  -> live pages are rewritten elsewhere
  -> zone becomes RECYCLED
  -> after delay and safety checks, DestroyZone deletes stream and index metadata

The stream layer is log/blob based. StreamImpl buffers records, writes record headers and block footers, supports aggregate flush profiles, rolls to a new blob when stream_max_blob_size would be exceeded, and uses tail scan on load for recovery.

GC And Compaction

Page GC

PageGc is zone based. It computes used bytes from Index::GetZoneStats, picks the lowest-utility frozen PageStore or oplog zone, scans slots for pages in that zone, and rewrites live pages through SlotStore. Empty or fully stale zones can be recycled and later destroyed.

Page Compaction

PageCompactor scans slots, groups page indexes by object, asks ModelManager::CompactPagesHint which pages to compact, loads those pages, calls ModelManager::CompactPages, writes new pages, marks old pages deleted by setting size zero, and commits index updates.

Eviction And Expiration

Expirer applies TTL cleanup through object metadata. Evicter chooses objects with an LRU-style policy and either deletes or dumps based on its actuator/config. Cache eviction frees memory; physical reclaim still depends on page/index/oplog lifecycle work.

Native Context Retrieve Path

RetrieveContextPack in src/extension/context/implement.cc is the C++ native hot path. It validates request shape, traverses nodes, applies placement/index filters, fetches candidates, scores, ranks, packs under budget, and returns compact telemetry.

RetrieveContextPack(request)
  -> ValidateRetrieveContextPackRequest
  -> CollectCandidateNodes
       query_vector present: TraverseContextTree using embeddings
       query_vector absent: QueryChildrenInternal breadth traversal
  -> ApplyPlacementFilter
  -> CollectIndexCandidates using compact buckets and IndexRef postings
  -> CollectNodeEventCandidates when no index filters
       candidate cache key includes scope, node, record type, append watermark, resource version
  -> CollectNodeSummaryAndCompressionCandidates
  -> NativeCandidateScore
       temporal decay + index boost + embedding boost
  -> score sort
  -> token-budget pack into ContextPackRef
  -> NativeRetrieveTelemetry

Telemetry fields

The C++ response includes selected/dropped counts, scanned records, index postings read, candidate fetch count, placement partitions touched, candidate cache hit, broad scan flags, per-stage latency, and filter/drop buckets.

Current serving posture

The intended production path is placement-key and index driven. Broad scan is treated as explicit fallback/debug. Python should consume the compact ContextPack and telemetry rather than materializing thousands of raw records.

What Looks Strong And What Still Needs Work

Strong pieces

  • Mature storage lifecycle loop with prepare, dump/reclaim, evict, expire, page GC, index GC, compaction, and metrics.
  • Compact page references and packed slot metadata.
  • PageStore zone state machine and stream/blob rollover/recovery.
  • Native C++ MatrixArk retrieve path with candidate cache, compact index prefilter, placement filtering, scoring, budget pack, and telemetry.

Gaps to keep watching

  • Public contract naming: C++ uses implementation names such as PageIndex, zone addresses, and oplog/page-store distinctions. Public reports should normalize these to PageAddress, BlockAddress, AppendWatermark, and CompactionWatermark.
  • Context performance: correctness must remain first. If selected refs are empty or drift from Rust/Python, latency/QPS numbers are not meaningful.
  • Physical reclaim: cache eviction is memory-only; durable reclaim depends on tombstones, index safety, follower cursor safety, page/block rewrite, and reclaimed-byte accounting.
  • Cold scan semantics: context temporal compression and storage GC should use no-cache/no-promote cold reads so serving cache is not polluted by old raw pages.
  • C++/Rust parity: reports should use the same top-level storage lifecycle, cache, stream, zone, page/block, and Raft shapes even if implementation internals differ.
