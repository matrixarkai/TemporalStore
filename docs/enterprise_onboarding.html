MatrixArk · Enterprise Onboarding

Give your app long-term memory in one API call.

Two HTTP endpoints — /v1/ingest to remember, /v1/retrieve to recall. Works from any language. No API key required to start. You control exactly whose memory it is.

Quickstart #

Point at your gateway (base_url = its origin, default port 8080). In the current default (dev) mode you don't need an API key — just send JSON.

1 · Remember something

curl -X POST http://saparo.ai:8080/v1/ingest \
 -H "Content-Type: application/json" \
 -d '{
   "kind": "message",
   "messages": [
     {"role":"user","content":"I prefer dark roast coffee"}
   ],
   "scope": {"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}
 }'

2 · Recall it

curl -X POST http://saparo.ai:8080/v1/retrieve \
 -H "Content-Type: application/json" \
 -d '{
   "query": "what coffee does alice like?",
   "scope": {"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}
 }'
# → context pack containing "dark roast coffee"

That's the whole loop. Everything below is detail on how memory is routed, how to ingest large files/skills, and how to lock it down for production.

The one concept: scope = identity & routing #

Memory is partitioned by a structured scope object — not parsed from the message text. The message content is what gets extracted (facts, entities, summaries, embeddings); who it belongs to is always explicit:

"scope": {
  "account_id": "acct_saparo",   // billing/org
  "tenant_id":  "saparo",        // your customer / workspace
  "user_id":    "alice",         // the end-user
  "session_id": "s-42"           // the conversation/session
}
FieldMeaningWhere it comes from
account_id / tenant_idBilling org / workspace — the hard isolation boundaryEnforced mode: pinned from the API key (un-spoofable). Dev mode: you assert it in scope.
user_id / session_idThe end-user & conversation — the per-user memory axisAlways from your request scope (your app vouches for it). Optional — omit for tenant-level memory.

Same scope in → same memory out. To store memory for a given user/session, pass that scope on ingest; to read it back, pass the same scope on retrieve.

Message & scope schema #

An ingest call = one scope (one user + session) + N messages (each with its own role). Identity is per-call; role is per-message.

{
  "kind": "message",              // message | resource | skill | feedback | business_data

  "scope": {                      // ── PER-CALL identity (applies to the whole batch) ──
    "account_id": "acct_saparo",  //   optional · pinned from the API key in enforced mode
    "tenant_id":  "saparo",       //   optional · pinned from the API key in enforced mode
    "user_id":    "alice",        //   optional · the end-user
    "session_id": "s-42"          //   optional · the conversation/session this batch belongs to
  },

  "messages": [                   // ── PER-MESSAGE role + content ──
    {"role": "user",      "content": "I prefer dark roast"},   // role ∈ {user,assistant,tool,system}
    {"role": "assistant", "content": "Noted."}                  // content = non-empty string
  ],

  "sharing_scope": "private_user",       // optional · private_user | tenant_shared | global_shared
  "ingestion_time_ms": 1699999999999      // optional · defaults to now
}

Validation (server-enforced — bad input → 400, never silent)

FieldRule
messages[]Non-empty list; each entry an object.
messages[].roleMust be one of user, assistant, tool, system.
messages[].contentNon-empty string.
scopeMust be an object (dict). Fields read individually; tenant_id/account_id overridden from the API key in enforced mode.

The minimum you must send

Only two fields are truly required — a message's role and content. Everything else has a default.

FieldRequired?If omitted →

Smallest valid call

  {"role":"user","content":"I like dark roast"}
]}
Smallest useful call (recommended) 
{"messages":[
   {"role":"user","content":"I like dark roast"}],
 "scope":{"user_id":"alice","session_id":"s-42"}}
One call = one session. session_id lives in scope, so it applies to the whole batch — every message in a single call must belong to the SAME conversation/user (extraction runs across the set). To ingest turns from different sessions or users, make a separate call per session. There is no per-message session field — this matches mem0 (run_id per add()) and Zep (session_id per add()).

Resources/skills replace messages with text (inline) or raw_uri (a stored blob) + resource_type; scope works the same way.

One schema for everything you ingest. This same envelope is the single, canonical schema for all ingestion kinds — message, feedback, resource, skill, business_data — across every entry point (/v1/ingest, /v1/ingest_file, and the SDK). The only separate format is the agent hook capture schema (Claude Code / Codex), which normalizes into this exact envelope before storage — so hook memory and API memory are stored identically.

Worked example: remember a chat turn #

Your app already has the pieces — you just wrap them. Nothing is parsed out of the text: content comes from the prompt/output, identity comes from your session.

# 1 · What your app already has (from YOUR runtime — NOT parsed from text)
tenant   = "saparo"     # your workspace   (or pinned from your API key in enforced mode)
user_id  = "alice"      # your end-user    (from your auth/session)
session  = "s-42"       # your conversation id

user_prompt      = "Set me up a monthly dark-roast subscription."     # what the user typed
assistant_output = "Done — monthly dark-roast subscription active."   # what your model replied

# 2 · Assemble the schema'd message:  text -> {role, content};  identity -> scope
payload = {
  "kind": "message",
  "scope": {"tenant_id": tenant, "user_id": user_id, "session_id": session},
  "messages": [
    {"role": "user",      "content": user_prompt},        # the PROMPT  -> user turn
    {"role": "assistant", "content": assistant_output},   # the OUTPUT  -> assistant turn
    # {"role": "tool",    "content": tool_result},        # (optional) tool output -> tool turn
  ],
}

# 3 · Ingest it (fire-and-forget; returns 202)
import requests
requests.post("http://saparo.ai:8080/v1/ingest", json=payload)

The full loop — recall before, remember after

S = {"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}

# BEFORE generating the next reply, recall relevant memory:
pack = requests.post("http://saparo.ai:8080/v1/retrieve",
        json={"query": new_prompt, "scope": S}).json()
#   → inject pack["selected_refs"] into your model's context, generate `reply`, then:

requests.post("http://saparo.ai:8080/v1/ingest", json={
  "kind":"message", "scope":S,
  "messages":[{"role":"user","content":new_prompt},
              {"role":"assistant","content":reply}]})
You have…Maps to…
the user's prompt{"role":"user","content": prompt}
the model's output{"role":"assistant","content": output}
a tool/function result{"role":"tool","content": result}
your session & end-userscope.session_id / scope.user_id (from your app, not the text)

Ingest one turn or a whole batch of turns from the same conversation in one call (one call = one session). No SDK needed — it's a plain JSON POST; ingest_text()/ingest_large_file() are just sugar over this.

Ingest API #

POST /v1/ingest — JSON body. Fast-acks 202; extraction runs asynchronously.

FieldReq?Notes
kindoptionalmessage (default) · resource · skill · feedback · business_data
messagesone of these[{"role":"user|assistant|system|tool","content":"…"}] — the content to remember
textone of theseInline content (for resource/skill) instead of messages
raw_urione of theseA stored blob to ingest, e.g. temporalstore://… (for large files — see below)
scopeoptional*Identity/routing (above). *Optional but you almost always want it.
sharing_scopeoptionalVisibility — private_user / tenant_shared / global_shared (see below). Sensible default if omitted.
resource_typeoptionalmd/pdf/txt… (inferred from filename when omitted)
waitoptionalfalse (default, async 202) or true (block until extraction finishes)

Minimum ingest: {"messages":[{"role":"user","content":"…"}], "scope":{"user_id":"alice","session_id":"s-42"}}

Retrieve API #

POST /v1/retrieve — returns a ranked context pack scoped to the caller.

FieldReq?Notes

Large files & skills #

A file on your machine must be pushed to the cluster (the server can't read your disk). Three ways — all idempotent (content-addressed by SHA-256):

A · One SDK call (Python)

from matrixark_ingest_client import ingest_large_file
ingest_large_file("onboarding_skill.md",
                  kind="skill", sharing_scope="tenant_shared")
# base_url / api_key default from env (MATRIXARK_BASE_URL / MATRIXARK_API_KEY)

B · One HTTP call — stream the file body

curl -X POST http://saparo.ai:8080/v1/ingest_file \
 -H "X-Resource-Kind: skill" -H "X-Resource-Type: md" \
 -H "X-Filename: onboarding_skill.md" \
 -H "X-Sharing-Scope: tenant_shared" \
 --data-binary @onboarding_skill.md

C · Two steps (max control)

# 1) upload → content-addressed key       2) ingest by reference
PUT  /v1/blob/resources/<sha2>/<sha256>      POST /v1/ingest
     --data-binary @file                        {"kind":"skill",
                                                  "raw_uri":"temporalstore://resources/<sha2>/<sha256>",
                                                  "resource_type":"md"}
temporalstore vs matrixobject. By default files land in TemporalStore's own blob tier (temporalstore://…) — works in Raft mode with no external object store. Enterprise deployments can target the MatrixObject store (matrixobject://…) via backend="matrixobject". Skills and resources share the same size limit; small content can be sent inline as text.

Visibility (sharing_scope) #

Controls who can retrieve what you ingest. Optional — omit and the server picks a sensible default.

sharing_scopeWho can see it
private_userOnly that user_id (the default when a user is set)
tenant_sharedAll users in the tenant
global_sharedEveryone

Cross-tenant access is impossible in enforced mode (the tenant is pinned from the key). Per-user separation relies on your app passing truthful user_ids.

Authentication & API keys #

Default is open (dev mode). Out of the box the gateway accepts anonymous requests — great for trials, but no tenant isolation (a one-time warning is logged). Turn on enforcement for production.

1 · Mint a key

python3 tools/matrixark_provision_api_key.py \
  --tenant-id saparo --account-id acct_saparo \
  --prefix mk_live --store /etc/matrixark/keystore.json
# prints the plaintext key ONCE (e.g. mk_live_xxxxx); stores only its sha256 hash
# restrict a key:  --scopes context:retrieve   --allowed-user-ids alice,bob

2 · Turn on enforcement

MATRIXARK_REQUIRE_AUTH=1  MATRIXARK_AUTH_ENFORCED=1 \
MATRIXARK_API_KEYS_HASHED_FILE=/etc/matrixark/keystore.json \
  uvicorn matrixark_v1_gateway:application --host 0.0.0.0 --port 8080

MATRIXARK_AUTH_ENFORCED is the edge gate — not MATRIXARK_ACCESS_MODE (that only affects the backend). Only the key hash lives at the edge; plaintext keys never sit on the gateway.

3 · Clients send the key

curl -H "Authorization: Bearer mk_live_xxxxx" … /v1/ingest
# tenant_id + account_id are pinned FROM the key — drop them from scope; still pass user_id/session_id

What a key carries & enforces

FieldEnforcedMeaning
tenant_id / account_id✅ pinnedisolation boundary — from the key, un-spoofable
status / expires_at_ms✅revoked / expired key → 401
scopes✅ per routecontext:ingest · retrieve · feedback · replay — wrong scope → 403
allowed_user_ids / allowed_session_ids✅ if setlock a key to specific users/sessions → else 403

401 = missing / invalid / expired key · 403 = valid key, wrong scope or user. Verified end-to-end: no-key→401, valid→202 (tenant pinned), spoofed tenant blocked, retrieve isolated across tenants, expired→401.

Python SDK vs raw HTTP #

Raw HTTP — any language

No install. JSON POSTs to /v1/* from requests, fetch, Go, curl…

import requests
BASE="http://saparo.ai:8080"
S={"tenant_id":"saparo","user_id":"alice","session_id":"s-42"}
requests.post(f"{BASE}/v1/ingest",
  json={"kind":"message",
        "messages":[{"role":"user","content":"likes dark roast"}],
        "scope":S})
requests.post(f"{BASE}/v1/retrieve",
  json={"query":"coffee?","scope":S}).json()

Python SDK — sugar over HTTP

Stdlib-only helpers. Only the file/text is required; the rest defaults from env.

from matrixark_ingest_client import (
    ingest_large_file, ingest_text)
ingest_text("Alice likes dark roast",
            kind="message")
ingest_large_file("skill.md",
            sharing_scope="tenant_shared")

Reliability & retries #

  • Idempotent uploads. Files are content-addressed (SHA-256) — re-sending the same bytes dedups, never duplicates. On any error, just retry the same call.
  • Integrity-checked on fetch. A corrupt/partial upload fails loudly (hash mismatch) instead of ingesting bad data — your cue to retry.
  • Bounded memory. /v1/ingest_file streams the body to disk in chunks; multi-GB files cost flat memory.
  • No half-writes. Extraction only runs after a successful upload — a failed upload leaves zero partial records.

vs mem0 & migrating #

Our message format is mem0's (OpenAI {role, content}), and we accept mem0's identity kwargs — so migration is close to a drop-in. The differences are additive: multi-tenant isolation and visibility levels that mem0's SDK doesn't have.
