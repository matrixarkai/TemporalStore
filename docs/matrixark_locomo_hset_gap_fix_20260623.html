MatrixArk LOCOMO HSET Gap Fix - 2026-06-23

What Was Fixed

The previous LOCOMO parity blocker was large matrixark_batch_extract workloads timing out on server-side hset for both C++ and Rust TemporalStore backends.

  • append_many(records) now exists on the MatrixArk adapter boundary.
  • C++ and Rust direct paths persist logical record batches as bounded record bundles.
  • Bundles are capped by MATRIXARK_DIRECT_RECORD_BUNDLE_MAX_BYTES, default 65536.
  • matrixark_batch_extract now flushes extracted records through append_many().

Remaining Boundary

The official 2-conversation / 100-question LOCOMO slice now passes on both backends. Full all-conversation LOCOMO needs explicit storage-engine/load shaping on this single-node local deployment.

Follow-up load-shaping support now exists: direct writes retry transient hset / put_string failures with exponential backoff, MATRIXARK_DIRECT_WRITE_THROTTLE_MS can pace sustained local benchmark writes, and retrieval audit writes can run in buffered, deferred, drop, or sync mode through MATRIXARK_DIRECT_AUDIT_MODE. Use deferred audit mode for full-dataset benchmark runs and flush audits at checkpoints or at the end.
