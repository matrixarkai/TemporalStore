MatrixArk Agent Integrations

Date: 2026-06-24

Goal

MatrixArk integrates with Codex, Claude Desktop, Cursor, and vertical AI agents through one stable context boundary.

Agent local context
-> MatrixArk MCP or HTTP API
-> TemporalStore-backed context retrieval / ingestion / feedback
-> ContextPack returned to the agent
-> agent combines ContextPack with local files, buffers, tools, and prompt

MatrixArk does not replace the agent's local context engine. It adds durable, time-aware, cross-session, cross-device, team-governed context.

Integration Modes

MCP Tool Integration

Best for Codex, Claude Desktop, Cursor, and other MCP-capable agents. The agent explicitly calls:

matrixark_retrieve
matrixark_ingest
matrixark_feedback
matrixark_session_commit
matrixark_replay

Hook Integration

Best for enterprise agent platforms and local tools that expose lifecycle hooks.

Before LLM:
  ingest current user message
  retrieve ContextPack

After LLM:
  ingest assistant answer, tool result, accepted refs, rejected refs

On Stop / task finished:
  commit pending same-session buffer

On PostCompact:
  ingest compacted summary
  commit pending same-session buffer

HTTP API Integration

Best for SaaS agents, enterprise gateways, and vertical Cursor-like products.

Cursor

Use the same MCP server shape. Cursor should keep its local codebase context and call MatrixArk for durable context such as decisions, team memory, resources, skills, and prior debugging outcomes.

Runtime Flow

User query
-> local context scan
-> matrixark_retrieve(query, scope, token budget, local refs)
-> MatrixArk query understanding
-> tree-first ContextNode traversal using L0/L1 embeddings
-> TemporalStore event/entity/resource/skill retrieval
-> staleness scoring + token-budget packing
-> ContextPack
-> agent combines local context + ContextPack
-> LLM answer/tool calls
-> matrixark_ingest / feedback / session_commit
-> async summaries, embeddings, compression, audit

Context Combination Policy

Agents should not blindly append MatrixArk context on top of unchanged local context forever. They should budget local and remote context together.
code-local question:
  local files first
  MatrixArk only for prior decisions, team memory, resources, skills

cross-session question:
  MatrixArk first
  local files only if current code state matters

current-state question:
  ContextEntity + fresh ContextEvent first
  stale blockers included only as warnings/evidence

resource/runbook question:
  selected ResourceChunk + citation
  do not inject full raw files by default

Access And Isolation

Every integration must carry account, tenant, user, and/or session scope. MatrixArk API keys enforce scopes, account and tenant isolation, allowed users and sessions, audit logs, key rotation, revocation, and optional SSO mapping.

What Is Automatic Today

MCP:
  tools are available to the agent, but calls are explicit

Codex hook:
  can auto-ingest user messages / tool results / stop events when configured

MatrixArk:
  extracts internal event/entity/segment/index data
  writes TemporalStore records
  refreshes summaries asynchronously
  returns ContextPacks
