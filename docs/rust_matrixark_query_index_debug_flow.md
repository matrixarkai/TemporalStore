# Rust MatrixArk Query, Index, Ingestion, Extraction, Retrieval Debug Flow

Last validated: 2026-06-23

This page mirrors the C++ debug flow at
`http://127.0.0.1:8081/docs/matrixark_query_index_debug_flow.html`, but runs the
Rust TemporalStore context pipeline through `context_workflow_harness`.

## What This Run Proves

- Backend: Rust `TemporalEngine` with local cache, page store, index-log, oplog,
  shared-store sync replay, shared-store async replay, and Raft read validation.
- Context extraction and retrieval are executed through Rust code, not a
  Python-only side store.
- ContextEvent, ContextIndexRef, ContextSummaryDirtyMarker, ContextSummary,
  ContextEmbedding, and ContextPackAudit data are persisted.
- Secondary-index replay is exercised through `ContextIndexRef` source indexes.
- Retrieval/injection selects context blocks and persists `ContextPackAudit`.
- Restart replay, shared-store sync/async, Raft read, and unified corpus gates
  passed in the same run.

| Area | C++ debug page | Rust debug run |

## Result

The Rust run passed the comparable end-to-end query/index debug flow for
ingestion, extraction, secondary-index persistence, retrieval, injection,
summary/embedding persistence, restart replay, shared-store sync/async replay,
Raft read validation, and unified corpus readiness.

Rust now emits the same behavioral query-understanding trace concepts used by
the C++ debug page: question type, secondary-index filter groups, verbose
filter-group pass/drop/selected counters, per-group candidate decision samples
with matched terms and drop reasons, candidate samples, tree traversal summary,
batched summary-embedding lookup evidence, and ranked selected refs. The remaining difference is transport shape:
the C++ page is generated by the MatrixArk MCP `temporalstore-direct` flow,
while this Rust page is generated by the Rust `context_workflow_harness`.
