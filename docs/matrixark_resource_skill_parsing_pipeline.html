MatrixArk Resource And Skill Parsing Pipeline

How MatrixArk parses resources and skills, chunks them, generates embeddings, extracts facts, and writes ContextNode, ContextSummary, ContextEmbedding, ContextEvent, ContextEntity, ContextIndex, ResourceManifest, ResourceChunk, SkillManifest, and SkillSection records.

Raw File Storage Modes

flowchart TD A["matrixark_ingest(kind=resource|skill, raw_uri, raw_storage_mode)"] B{"raw_storage_mode"} C["local: keep local file URI/path"] D["cloud: upload local file or inline text to S3"] E["download/read S3 object for parser input"] F["parse chunks, summaries, embeddings, indexes"] G["TemporalStore records store raw_uri only, never raw bytes"] A --> B B --> C --> F B --> D --> E --> F F --> G

Local Mode

Set raw_storage_mode=local, or omit it when deployment_scope is not cloud. MatrixArk stores the caller-provided raw_uri, reads the local path directly, and keeps raw bytes out of TemporalStore.

Cloud Mode

Set raw_storage_mode=cloud, or set deployment_scope=cloud. MatrixArk uploads local files or inline text to S3, stores the resolved s3://bucket/key URI, downloads the object for parser input, and rewrites citations to the S3 URI.

Cloud imports use s3_bucket or MATRIXARK_RESOURCE_S3_BUCKET, plus optional s3_prefix or MATRIXARK_RESOURCE_S3_PREFIX. S3-compatible deployments can set MATRIXARK_S3_ENDPOINT_URL or AWS_ENDPOINT_URL_S3.

Import tasks, manifests, registries, chunks, and list APIs expose requested_raw_uri, raw_storage_mode, raw_storage_policy, upload_status, cloud_bucket, and cloud_key.

Current Resource Flow

flowchart TD A["matrixark_ingest(kind=resource, raw_uri, resource_type, scope, metadata.node_path)"] B["ResourceImportTask queued/running"] C["ResourceParser dispatch by type"] D["Parse into bounded cited chunks"] E["Dedupe chunks by content_hash"] F["Generate chunk embeddings"] G["Write resource records"] H["Extract resource facts"] I["Mark node summary dirty"] J["ResourceImportTask completed"] A --> B --> C --> D --> E --> F --> G --> H --> I --> J

Callers send a simple resource request. MatrixArk validates the source, creates a resource_import_task, dispatches the parser, creates cited chunks, dedupes by content_hash, generates embeddings, writes registry and context records, extracts resource facts, and marks the target node summary dirty.

Supported parser inputs include .md, .txt, .log, .html, .pdf, .docx, .pptx, .xlsx, .csv, .tsv, .json, .jsonl, local directories/repos, and images/scanned documents through the OCR/VLM command path when configured.

Raw bytes are not copied into TemporalStore. TemporalStore stores raw_uri, parsed chunks, citations, summaries, embeddings, indexes, registry records, task state, and replay metadata.

Chunking

InputChunking Strategy
Markdown, HTML, text, logsHeading-aware sections, then bounded token/character windows.
CSV, TSV, XLSXRow-group/table chunks instead of one tiny row per chunk.
JSON, JSONLTop-level object/path chunks or record groups.
PDF, PPTX, DOCXPage, slide, paragraph, and table-derived chunks.
Code and directoriesRelative path metadata, symbol-aware parsing when available, fallback token windows.
Images/scanned PDFsVLM/OCR caption chunks when configured; otherwise parse warnings.

Each resource_chunk carries chunk_hash, source_ref, text, token_estimate, content_hash, resource_version, unit_kind, relative_path, and optional heading_slug, page_number, slide_number, row_range, and parse_warnings.

Embeddings

flowchart LR A["Chunk text"] B["embedding_text_for_chunk()"] C["Adds source path, headings, columns, keywords"] D["embedding_for_text() / embeddings_for_texts()"] E["context_embedding record"] A --> B --> C --> D --> E

Stored chunk text stays citation-friendly. Embedding text is richer: it can include source ref, relative path, heading path, table columns, keywords, and content. This improves retrieval without polluting the final prompt with metadata-heavy text.

context_embedding records are written for resource_chunk, resource_l0, skill_l0, skill_summary, resource-derived event_text, resource-derived entity_state, and node L0/L1 summaries.

Resource Records Written

Import And Registry

resource_import_task, resource_manifest, and resource_registry track lifecycle, identity, version, parser metadata, and access scope.

Serving Units

resource_chunk stores bounded cited text. context_summary stores L0 summaries for traversal and preview.

Retrieval Structures

context_embedding stores vectors. context_index stores filters like source type, resource type, unit kind, keyword, heading, and path.

Extracted Memory

context_event and context_entity store facts such as owners, approvals, deadlines, policies, costs, procedures, risks, and API contracts with source chunk refs.

Skill Flow

flowchart TD A["matrixark_ingest(kind=skill, raw_uri=SKILL.md or bundle)"] B["SkillParser"] C["Parse front matter and body"] D["Extract triggers/tools/scope/version/status"] E["Parse skill body into sections"] F["Write skill manifest and registry"] G["Write skill sections"] H["Generate skill summary/chunk embeddings"] I["Index skill_trigger and skill_tool"] J["Retrieve only relevant skill sections into ContextPack"] A --> B --> C --> D --> E --> F --> G --> H --> I --> J

The skill parser extracts name, description, triggers, allowed_tools, owner_scope, examples, permissions, inputs, outputs, precedence, status, version, category, and bundle metadata.

Records written include skill_manifest, skill_registry, skill_section, resource_chunk(resource_type=skill), context_summary(skill_l0), context_embedding(skill_summary/skill_l0/resource_chunk), and context_index(skill_name/skill_trigger/skill_tool/source_type/resource_type).

ContextNode And Summaries

flowchart TD A["metadata.node_path or default session node path"] B["ensure_context_node_path()"] C["ContextNode chain materialized"] D["Resource/skill/event records attach to leaf node_hash"] E["append_node_summary_embeddings()"] F["context_summary node_l0/node_l1"] G["context_embedding node_l0/node_l1"] H["context_summary_dirty for async parent refresh"] A --> B --> C --> D --> E --> F --> G D --> H

Callers do not manually create ContextNode records. MatrixArk materializes a node path from metadata.node_path or a default session/resource path. Records attach to the leaf node, while summary dirty markers allow parent refresh to happen asynchronously.

Default summary refresh cadence: the MCP summary refresher wakes every MATRIXARK_SUMMARY_REFRESH_INTERVAL_MS, default 1000 ms, and refreshes up to MATRIXARK_SUMMARY_REFRESH_LIMIT, default 64, dirty nodes per tick. It writes versioned ContextSummary(node_l0) and ContextEmbedding(node_l0) for every refreshed node, and writes node_l1 summaries/embeddings when the node has enough accumulated content, child summaries, or event volume to need a richer overview.

Session/resource boundaries may still call matrixark_refresh_summaries immediately when the caller needs freshness before retrieval. If L0/L1 summaries are missing or stale, retrieval falls back to event, entity, chunk, and recent raw embeddings. Summaries are an optimization, not a correctness dependency.

Retrieval

flowchart TD A["matrixark_retrieve(query, scope, max_context_tokens)"] B["Infer query type and secondary index filters"] C["Scope filter: account/tenant/user/session/team"] D["Tree-first traversal using node L0/L1 embeddings"] E["Secondary index prefilter"] F["Score resource chunks, skill sections, events, entities"] G["Apply version/stale/superseded rules"] H["Question-type-aware packing"] I["ContextPack + ContextPackAudit"] A --> B --> C --> D --> E --> F --> G --> H --> I

Resource chunks and skill sections are selected separately. Disabled skills are excluded. Superseded chunks are excluded unless historical replay is requested. ContextPack audit records selected and dropped refs, scores, token cost, version, stale/superseded state, access decision, and citation.

  • Facts: extracted resource/event observation first.
  • Procedures: relevant skill section or troubleshooting chunk first.
  • Evidence: raw cited chunk first.
  • Current state: entity state plus source chunk/event.
  • Broad exploration: L0/L1 summaries first.

Injection Completeness Gate

The resource/skill parity runner now fails unless the complete serving model is injected and replayable.

AreaRequired records
TreeContextNode, ContextChildRef, ContextSummary, ContextSummaryDirty

Skill lifecycleSkillManifest, SkillRegistry, SkillSection, skill-backed ResourceChunk
Facts and stateresource-derived ContextEvent, resource-derived ContextEntity
Serving indexesContextEmbedding, ContextIndex for resource type, skill trigger/tool, keyword, heading, unit kind, event type, and entity type
Replay and governanceContextPackAudit, access-management audit rows for list/update/retrieve/replay

Product boundary: resource files are fact sources, so MatrixArk extracts decisions, policies, owners, costs, approvals, troubleshooting steps, and API contracts into ContextEvent / ContextEntity records with source citations.

Skill files are instruction sources. MatrixArk stores them as manifests, registries, sections, summaries, embeddings, and indexes. It does not convert skill instructions into business facts by default; retrieval selects only relevant skill sections into the ContextPack.

Debug Checklist

  1. resource_import_task: lifecycle and parser status.
  2. resource_manifest / skill_manifest: identity, version, parser metadata.
  3. resource_registry / skill_registry: discovery and access scope.
  4. resource_chunk / skill_section: cited serving units.
  5. context_embedding: chunk, summary, fact, and entity vectors.
  6. context_index: filterable fields.
  7. context_event: extracted facts.
  8. context_entity: evolving state.
  9. context_summary: L0/L1 traversal summaries.
  10. context_pack_audit: selected and dropped refs.
