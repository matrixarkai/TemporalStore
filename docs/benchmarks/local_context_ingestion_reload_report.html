Findings

Fresh start

All stable local context records were accepted with zero failures.

The loader now uses a 256 MB default cache and immediately promotes packed context pages into memory on batched append. First-load reports show positive memory_bytes and memory_fills.

Normal restart

Checkpoint-only restart warms memory without ingesting duplicate stdin.

Both Claude and Codex replayed persisted local records and filled memory cache in about 30 ms on this small stable sample.

Duplicate/resume

Second identical load skipped 100% covered rows.

The skip path proves coverage against the same session-index node hashes used by ingestion; accepted and failed were both 0.

Full-corpus note

The code path is fixed and validated on a stable bounded artifact. The full Windows-mounted transcript scan was intermittently slow/nonzero during this turn, so full-corpus validation remains active goal work.

Implementation Changes Validated

  • MATRIXARK_BACKFILL_CACHE_BYTES controls local-context backfill cache size; default is 256 MB.
  • MATRIXARK_BACKFILL_FLUSH_EVERY_ACCEPTED checkpoints during large raw-first backfills; default is 10,000.
  • --checkpoint-only / MATRIXARK_BACKFILL_CHECKPOINT_ONLY=1 loads and flushes the shard index without consuming duplicate local-context input.
  • MATRIXARK_BACKFILL_SKIP_COVERED_SESSIONS=1 skips rows whose expected node hashes already exist in the session index.
  • Batched packed-page writes now place the just-written page bytes into memory cache immediately.
