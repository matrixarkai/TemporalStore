LOCOMO Benchmark Workflow: C++ TemporalStore vs Python Memory

This walkthrough shows how LOCOMO conversations become MatrixArk context records, how retrieval builds a ContextPack, and what differs when the same pipeline uses Python memory versus C++ TemporalStore as the storage boundary.

What LOCOMO Tests

Single-hop
One turn contains the answer.
Multi-hop
The answer requires combining multiple turns or sessions.
Temporal
Questions depend on dates, before/after, or current/latest state.
Updates
Newer facts supersede older facts while old evidence remains replayable.

End-To-End Workflow

1. LoadLOCOMO JSON sessions and QA.
2. BatchSession turns become message batches.
3. ExtractOne pass emits events, entities, summaries, indexes, segments.
4. StorePython memory or C++ TemporalStore record log.
5. RetrieveDense, sparse, keyword, time-decay recall.
6. PackQuestion-type token-budgeted ContextPack.
7. JudgeDeterministic, OSS, or OpenAI-compatible reader/judge.

Example A: Approval And Budget

Session date: 2026-06-01
User: Alice says the GPU purchase request needs finance review.
Assistant: Bob says the requested budget is $42,000.
User: Alice approved the GPU purchase after finance review.

Question: Who approved the GPU purchase?
Answer: Alice.

MatrixArk writes ContextEvent records for each turn, ContextIndex terms for approval/budget keywords, ContextSummary for the batch L0 summary, ContextEmbedding for event and summary scoring, and a ContextSegment for the coherent approval topic. Retrieval promotes the exact approval event through lexical score, dense score, node summary score, and time decay.

Example B: Preference Supersession

Session date: 2026-06-03
User: I prefer Python for dashboards.

Session date: 2026-06-12
User: Actually, I prefer Rust for low-latency storage work now.

Question: What language does the user currently prefer for low-latency storage?
Answer: Rust.

MatrixArk writes old and new events, then updates a ContextEntity of type preference. The old Python preference remains replayable but becomes stale for current-state questions. The pack should include the Rust entity state first and the stale blocker only if useful.

Example C: Temporal Location

Session date: 2026-03-02
User: I moved to Seattle today.

Session date: 2026-04-10
User: I moved to Austin for the new infra project.

Question: Where was the user before April 10?
Answer: Seattle.

The query planner recognizes a historical before-date question. It should retrieve the Seattle event as the answer and may include Austin as the boundary event. For current-state questions, the location entity would answer Austin first.

Injected Data Models

ModelWhen WrittenBenchmark Role
ContextEventEvery message or extracted memory event.Raw replay evidence and event timeline.
ContextEntityDurable evolving facts such as preference, location, relationship, status, plan.Answers current-state and update questions before raw scans.
ContextSummaryBatch/session/node L0 or L1 summary.Tree/node scoring and token-efficient recall.
ContextEmbeddingEvent, entity, segment, and summary embeddings.Exact scoring inside TemporalStore-backed record set without a separate VectorDB.
ContextIndexEvent type, scope, entity type, and keyword terms.Filtering, lexical fallback, and keyword-path recall.
ContextSegmentHigh-saliency coherent topic segment.Answer-dense evidence instead of noisy raw chunks.
ContextCompressionEventOld/cold time-window summary.Compression with replayable source refs and safety gate.
ContextPackAuditEvery retrieval.Replay selected/dropped refs, token accounting, and score debugging.

Recall And Packing

Sfinal = (1 - wtime - wbusi) * Sorigin + wtime * Stime + wbusi * Sbusi

Sorigin combines dense similarity, sparse lexical score, node score, and segment signals. Stime applies freshness and decay. Sbusi boosts important event types or instance-level business priority.

  • Date questions: session date plus exact turn.
  • Fact questions: extracted observation first.
  • Evidence questions: raw dialogue first.
  • Multi-hop questions: multiple sessions/entities.
  • Current-state questions: entity state plus stale blockers.

Takeaway: Python memory proves the MatrixArk logic quickly. C++ TemporalStore proves the same logical context records survive the production storage boundary. The target is identical benchmark behavior while TemporalStore remains the single serving store for events, entities, summaries, indexes, embeddings, compression, and context-pack audits.
