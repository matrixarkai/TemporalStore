# MatrixArk Agent Context Envelope

Date: 2026-06-25

## Product Rule

Agents should send as much useful context as they already know, but they should not be trusted as the final authority for identity or access. MatrixArk accepts the agent-provided envelope as hints and evidence, then resolves and enforces the final `account_id`, `tenant_id`, `user_id`, `session_id`, API key scopes, roles, SSO mapping, audit, and per-user/session isolation on the server side.

This is the safe model for Codex, Claude, Cursor, and other AI agents:

```text
agent sends what it knows
-> MatrixArk normalizes the envelope
-> API key / SSO / local mode resolve identity
-> access scope filters every write and retrieval
-> audit records what was accepted, inferred, rejected, and replayed
```

## What Codex Can Send

Codex can integrate with MatrixArk through MCP calls or lifecycle hooks. The current Codex manual documents MCP configuration and hook events such as `UserPromptSubmit`, `PostToolUse`, `PreCompact`, `PostCompact`, `Stop`, `SessionStart`, and others. Practically, MatrixArk should expect Codex to provide some of these fields when available, not all of them every time.

| Category | Examples Codex or a Codex hook may know | MatrixArk use |
|---|---|---|
| Prompt text | `prompt`, `user_prompt`, `input`, `turn.input`, `messages[].content` | Ingest as `ContextEvent`; retrieve before LLM. |
| Assistant/tool result | `tool_name`, `tool_input`, `tool_output`, `status`, terminal output | Ingest as tool/result evidence and possible feedback. |
| Session/thread clues | `session_id`, `thread_id`, `conversation_id`, `transcript_id`, transcript path | Derive `session_id` hint; MatrixArk resolves final session scope. |
| Workspace clues | `cwd`, `workspace_root`, `project_root`, repository path | Store as metadata; useful for node defaults and replay. |
| Local context refs | open files, active files, selected text, buffers, terminal output, tool outputs | Pass to `retrieve.local_context` so MatrixArk can dedupe and fill remaining prompt budget. |
| Resource/skill files | `raw_uri`, `path`, `file_path`, `document_path`, `SKILL.md` | Ingest as resource/skill; parse/chunk/embed/extract. |
| Browser/app context | current URL, page title, visible selection, screenshots/asset refs when the agent exposes them | Store as metadata or resource refs. |
| Feedback signals | accepted refs, rejected refs, `context_pack_id`, confirmation/correction text | Store as feedback memory and replayable audit. |

Codex does not automatically expose a stable MatrixArk account/user schema. For local hooks, default identity comes from config/env (`MATRIXARK_ACCOUNT_ID`, `MATRIXARK_TENANT_ID`, `MATRIXARK_USER_ID`) or local defaults. For cloud/product mode, MatrixArk API keys and optional SSO mapping become authoritative.

## Minimal Message Ingest

An agent can send only a message. MatrixArk will fill local defaults for missing scope in local/dev mode.

```json
{
  "messages": [
    {"role": "user", "content": "Alice approved the GPU purchase after finance reviewed the budget."}
  ]
}
```

MatrixArk normalizes this into a scoped event. In local mode defaults are:

```text
account_id = acct_local
tenant_id  = derived from agent name when known, otherwise tenant_local/user default
user_id    = local OS user or MATRIXARK_LOCAL_USER_ID
session_id = provided/captured when possible; otherwise optional or generated by hook state
```

## Recommended Rich Envelope

When an agent knows more, send it. This is the recommended rich envelope for Codex/Claude/Cursor-style hooks:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "What is the current GPU approval and runbook blocker?",
      "created_at_ms": 1782415000000
    }
  ],
  "scope": {
    "account_id": "acct_hint_from_hook_or_config",
    "tenant_id": "tenant_codex",
    "user_id": "local_or_sso_user_hint",
    "session_id": "codex:thread-abc"
  },
  "metadata": {
    "source": "codex_hook",
    "agent": "codex",
    "agent_event": "UserPromptSubmit",
    "agent_context": {
      "workspace_root": "/repo/path",
      "current_url": "http://127.0.0.1:8081/docs/debug.html",
      "tool_name": "Bash",
      "local_context": [
        {"ref": "src/service.py", "kind": "python", "text": "open buffer or snippet"},
        {"ref": "terminal", "text": "recent command output"}
      ],
      "payload_keys": ["prompt", "cwd", "open_files"]
    }
  },
  "agent_hook": {
    "source": "codex",
    "hook_type": "before_llm",
    "auto_captured": true,
    "hook_id": "codex:UserPromptSubmit:1782415000000",
    "observed_at_ms": 1782415000000,
    "trigger": "UserPromptSubmit",
    "session_id_source": "payload_field"
  }
}
```

MatrixArk treats `scope` fields from the agent as hints unless an API key/SSO/local policy confirms them. The final scope is written into records and audits.

## Retrieval With Local Context

For retrieval hooks, the agent should pass local context it already selected. MatrixArk then returns only remote/shared memory needed to fill the remaining budget.

```json
{
  "query": "What is the current GPU approval and blocker?",
  "scope": {"user_id": "deeproute", "session_id": "codex:thread-abc"},
  "max_context_tokens": 1200,
  "local_context": [
    {"ref": "open-buffer:main.py", "text": "current local code context"},
    {"ref": "terminal:last-command", "text": "recent test output"}
  ]
}
```

This avoids blindly adding remote context on top of local context. MatrixArk can dedupe local refs, reserve budget for them, and return a compact ContextPack with selected remote events/entities/resources/skills.

## Resource And Skill Files

Agents can send files in two ways:

| Mode | Agent sends | MatrixArk does |
|---|---|---|
| Local mode | `raw_uri` as local path or `file://` path | Store URI, parse local file, write chunks/summaries/embeddings/indexes. |
| Cloud mode | local path, uploaded URL, or inline text | Upload to S3 when configured, store S3 `raw_uri`, parse from S3/local temp, never store raw bytes in TemporalStore. |
| MCP direct | `matrixark_ingest(kind=resource|skill, raw_uri=...)` | Runs resource/skill import task lifecycle. |

For `SKILL.md`, MatrixArk should parse skill-specific fields into `SkillManifest`, `SkillSection`, `ResourceChunk(resource_type=skill)`, skill summaries, embeddings, and indexes. It should retrieve only relevant skill sections, not the whole skill bundle by default.

## Lifecycle Mapping

| Agent lifecycle | MatrixArk action |
|---|---|
| `SessionStart` | Optionally load prior ContextPack or session summary. |
| `UserPromptSubmit` / before LLM | Ingest user message, pass local context, retrieve ContextPack. |
| `PostToolUse` | Ingest tool result as replayable evidence. |
| Assistant answer / `Stop` | Ingest assistant answer; commit pending session window. |
| `PostCompact` | Ingest compacted session summary; commit pending window. |
| Idle timeout | Commit pending session window. |
| Resource added | Ingest resource/skill file. |
| Feedback/confirmation | Store accepted/rejected refs, correction, or confirmation; link to prior ContextPack when available. |

## What MatrixArk Should Enforce

MatrixArk should always enforce these server-side, even if the agent sends hints:

- API key validity, roles, scopes, rotation, revocation.
- Account and tenant membership.
- User/session isolation.
- SSO mapping from Okta/Google/Azure AD identities to MatrixArk user IDs.
- Access filtering before scoring resources, skills, entities, events, and chunks.
- Audit logs for ingestion, retrieval, feedback, replay, resource import, and admin actions.
- Replayable `prior_refs`, selected refs, dropped refs, and context-pack audits.

## Implementation Status

Current MatrixArk hook support:

- `tools/matrixark_codex_hook.py` captures Codex prompt/session/workspace/local context hints, sends message ingestion, local-context-aware retrieval, and session commits.
- `tools/matrixark_agent_hook.py` is the generic adapter for Claude/Cursor/Windsurf/Cline/Roo/Continue/Copilot/OpenCode/Aider/Gemini and other agents. It accepts permissive payload shapes and normalizes them.
- Both hooks now store `metadata.agent_context` and pass `local_context` to retrieval when present.
- MatrixArk server still resolves final identity from local defaults, API keys, SSO mapping, and access management.

## Product Position

The agent should not be forced to understand MatrixArk internal data models. It should send a simple, rich envelope containing messages, local context refs, files/resources, lifecycle event, and any identity/session hints it knows. MatrixArk owns extraction, entity updates, summaries, embeddings, tree traversal, access control, and replay.
