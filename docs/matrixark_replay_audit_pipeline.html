MatrixArk Replay And Audit Pipeline

Replay and audit are wired for MatrixArk context retrieval. Retrieval writes context_pack_audit, operational and access actions write matrixark_audit_log, and matrixark_replay can return the persisted record stream needed to reconstruct selected evidence.

Why This Matters

Replay and audit answer what MatrixArk returned, why those refs were selected, what was dropped, which token budget and retrieval policy were used, and which account, tenant, user, session, or API key performed the action.

What context_pack_audit Stores

Identity

context_pack_id, query, scope, created_at_ms.

Evidence

selected_refs, dropped_refs, selected ref counts, compact source previews, citations.

Retrieval

tree_traversal, secondary_index_filter, recall_policy, layer scores, candidate counts.

Budget

Local, remote, and total prompt context tokens plus the remote context budget.

Selected And Dropped Refs

selected_refs preserve ref_type, ref_hash, node_path, source_ref, score, selection_reason, matched_index_terms, token estimate, and citation metadata where available.

dropped_refs explain failure and tuning causes: over_budget, duplicate, stale_or_superseded, low_score, access_scope_denied, secondary_index_filter_miss, or disabled_skill.

MatrixArk writes matrixark_audit_log for actions such as context.ingest, context.retrieve, context.replay, resource.list, skill.list, skill.update, backend readiness, backend metrics, and admin/account/key operations.

Replay API

{
  "name": "matrixark_replay",
  "arguments": {
    "context_pack_id": "123"
  }
}

The current replay implementation flushes pending audit buffers, returns the stored records for the current backend/prefix, and lets the consumer find the matching context_pack_audit by context_pack_id. This works across local JSONL, C++ direct, and Rust record-log backends.

Audit Buffering

Direct C++ and Rust-backed adapters support audit modes:

  • sync: write audit immediately.
  • buffered: buffer and flush in the background to reduce retrieval tail latency.
  • drop: skip ContextPack audit writes for extreme load testing only.

matrixark_replay calls flush_audits() first, so replay can see the latest buffered ContextPack audit before returning records.

Resource replay uses resource_chunk refs. Skill replay uses skill_section refs. For skills, MatrixArk writes skill_manifest, skill_registry, skill_section, skill-as-resource resource_chunk, skill_l0 summary, and embeddings for skill_l0, skill_summary, skill_section, and resource_chunk.

C++ And Rust Status

The resource/skill backend parity harness validates the same replay/audit contract for local JSONL, C++ TemporalStore, and Rust TemporalStore record-log backends. It checks context_pack_audit, replayable selected refs, resource chunk replay, skill section replay, and access audit for retrieve/replay/resource/skill actions.

Current Limitations

  • Replay currently returns the backend record stream plus matching audit data. A narrower replay bundle can be added later for production APIs.
  • Buffered audit mode can lose the newest unflushed audit records if the process crashes. Use sync mode for regulated or benchmark runs.
  • Audit logs do not store raw resource bytes. They point to raw_uri, source_ref, chunk hashes, and selected record refs.

Recommended Production Policy

Use buffered ContextPack audit for normal serving, sync audit for regulated or benchmark runs, keep access audit enabled, and always record selected refs, dropped refs, token counts, tree traversal, and secondary-index filter details.
