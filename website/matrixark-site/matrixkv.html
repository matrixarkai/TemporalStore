Platform

MatrixKV

Strongly consistent KV for metadata and control-plane state.

MatrixKV is the MatrixArk consistency foundation: routing metadata, table state, leases, transactions, timestamps, and other records where correctness matters more than raw cache throughput.

Product Advantages

Why MatrixKV over using a cache for metadata?

01

Correctness-first state

Leases, epochs, routing, and table metadata need committed state, not eventual cache freshness.

02

Control-plane fit

MatrixKV is positioned for metadata and coordination that support MatrixArk engines and managed cloud operations.

03

Consistency boundary

It gives the platform a place to put strong state while TemporalStore and MatrixDB focus on serving performance.

04

Operational clarity

Separating metadata KV from hot serving data makes failure handling, ownership, and routing easier to reason about.

System Architecture

Client / proxy Master TSO Partition server Raft log Storage engine

MatrixKV is the consistency-oriented member of the MatrixArk family. It is not the default engine for high-cardinality temporal serving; it is the place to put metadata, leases, timestamps, and transactional coordination.

Serving Workflow

  1. Client or platform component submits a metadata or KV operation.
  2. Routing resolves the partition and current leader.
  3. Writes commit through the consistency path before becoming visible.
  4. Consumers use the committed state for routing, leases, and table metadata.
