# AI Agent Context Envelope

MatrixArk should expose a simple Zep/Mem0-style ingestion contract and hide the
TemporalStore serving schema. The caller sends chat messages, scope, metadata,
and optional hook evidence. MatrixArk always owns extraction, node selection,
indexing, summary generation, embeddings, compression, and replay.

For the complete MatrixArk API and schema reference, including MCP tools and
internal TemporalStore APIs, see `MATRIXARK_API_REFERENCE.md`.

The same envelope can be sent manually through API/MCP or captured automatically
through host-agent hooks. Hooks are the preferred path for vertical Cursor
companies because MatrixArk can observe the full event loop without asking the
LLM agent to remember to call an ingest tool.

## Default Contract

Minimal ingest request:

```json
{
  "messages": [
    {"role": "user", "content": "Alice approved the GPU request."}
  ]
}
```

Recommended v1 request shape when the agent has scope and source hints:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Alice approved the GPU request.",
      "name": "Alice",
      "created_at_ms": 1781500000000
    }
  ],
  "scope": {
    "user_id": "alice",
    "session_id": "agent-session-scale-1",
    "team": "infra_team",
    "project": "project_1"
  },
  "metadata": {
    "source": "cursor",
    "node_path": ["company_a", "infra_team", "project_1", "approvals"]
  }
}
```

Required customer-facing fields:

```text
messages[].role
messages[].content
```

Optional fields:

```text
scope.user_id          optional user memory scope
scope.session_id       optional thread/run scope
scope.team/project     routing and filtering hints
messages[].name        optional actor/tool/agent label
messages[].created_at_ms optional source event time
metadata.source        optional source label
metadata.node_path     optional tree/path hint
metadata.reply_to_*    optional feedback linkage
agent_hook             optional; only for auto-captured hooks
```

`scope.session_id` is optional for the public API, but strongly recommended.
The minimum useful scope is either `scope.user_id` or `scope.session_id`. If a
caller sends both, MatrixArk can do both long-term user memory and precise
same-thread grouping. If a caller only sends `scope.user_id`, MatrixArk uses
that as user-level memory. If a caller only sends `scope.session_id`, MatrixArk
uses it as thread/run memory. Host-agent hooks should auto-capture both whenever
the agent exposes them.

MatrixArk can fill these internally when omitted:

```text
tenant_hash       from auth or API key
message_id        generated by MatrixArk
ingestion_time_ms current server time
kind              message, feedback, resource, or business_data endpoint
node_path         from model/rule extraction plus scope hints
```

## Extraction Semantics

MatrixArk always runs extraction and canonicalization. Callers do not decide
whether extraction happens; they only provide the source message, scope, metadata,
and any optional agent-provided hints.

```text
message/resource/feedback
-> MatrixArk extraction and normalization
-> internal ContextEvent / ContextEntity / ContextIndex records
-> ContextSummary and ContextEmbedding records
-> ContextCompressionEvent and ContextPackAudit when needed
```

The MVP can use deterministic local extraction for tests, OSS models for local
Docker, OpenAI/provider models in production, or optional
`metadata.agent_extraction` hints from the host agent. MatrixArk validates and
normalizes those hints into its own internal TemporalStore model. Customers do
not define serving schemas in v1.

## Hook Capture Option

Manual API/MCP calls are enough for early integrations, but production agent
runtimes should install MatrixArk as a hook around the event loop:

```text
before_llm       user query and local-context hints before the model call
after_llm        final answer, selected refs, rejected refs, and commitments
tool_result      tool input/output, status, and source refs
resource_added   uploaded/attached file, URL, PDF, markdown, or runbook ref
feedback         user confirmation, correction, rating, or explicit rejection
session_commit   end-of-thread batch commit for messages not sent earlier
```

Hook metadata is small and sits beside the same agent envelope:

```json
{
  "agent_hook": {
    "source": "matrixark-sdk",
    "hook_type": "before_llm",
    "hook_id": "hook-before-approval-1",
    "observed_at_ms": 1781500000000,
    "idempotency_key": "scale-api-approval-1",
    "trigger": "user_message",
    "auto_captured": true
  },
  "agent_envelope": {
    "messages": [
      {"role": "user", "content": "Alice approved the GPU request."}
    ],
    "scope": {"team": "infra_team", "project": "project_1"},
    "metadata": {"source": "cursor"}
  }
}
```

Recommended deployment options:

```text
SDK middleware  wrap the agent loop and call MatrixArk before/after LLM calls
MCP server      expose retrieve/ingest/feedback tools for agents that support MCP
IDE/plugin      capture selected files, user turns, tool output, and final answer
sidecar daemon  local/on-prem process that batches approved hook events
gateway/proxy   enterprise or vertical-agent request path with centralized policy
```

Hooks do not bypass consent or governance. The host application should decide
which lifecycle events are allowed, redact secrets before sending, and use
idempotency keys so retries do not duplicate memories.

## Feedback And Confirmation

MatrixArk cannot reliably know that a short message such as `yes`, `confirmed`,
or `looks good` is a confirmation without prior context. It needs at least one of:

```text
context_pack_id
metadata.reply_to_context_pack_id
accepted_refs / rejected_refs
assistant message being confirmed
previous thread messages in the same session
```

This follows the same product shape as Mem0-style memory ingestion: the caller
sends messages plus a scope id, then the memory service decides what to extract.
For MatrixArk, `scope.session_id` is the preferred thread/run key. If a short
feedback message arrives, MatrixArk first looks for explicit prior context, then
previous messages in the same session scope. The best key is
`user_id` + `session_id` + `team`; `session_id` + `team` is also valid when the
agent does not expose user identity. If `session_id` is missing, MatrixArk may
fall back to previous messages for the same `user_id` + `team`, but it must
attach a quality warning because this is user-level memory, not same-thread
evidence. If no prior context is available, MatrixArk stores the message but
marks classification as `AMBIGUOUS`.

For extraction, MatrixArk should pass a bounded prior-context window to the
internal extraction/provider when prior context exists. The MVP uses:

```text
context_pack_id / reply_to_context_pack_id -> ContextPack summary + refs first
then same-session summary for the same context node before raw prior events
then same-user summaries/entity state before raw prior events as a weaker fallback
cap prior text at 4 KB and at 8 raw events
record prior_refs, prior_summary_count, and prior_message_count for replay
```

This mirrors the memory-provider pattern: agents send new messages, while the
memory service supplies recent thread context and compact older summaries or
existing memories to extraction. Normal message/business/resource extraction can
still proceed without prior context; prior context just improves quality. Short
feedback such as `yes` or `wrong` needs prior context to become a confident
confirmation or correction. MatrixArk should prefer pack summaries, session
summaries for the same context node, and entity state before raw prior messages,
and should never hand an unbounded session transcript to the model.

Example feedback payload:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Yes, that rollback answer is correct.",
      "name": "Alice",
      "created_at_ms": 1781500004100
    },
    {
      "role": "assistant",
      "content": "The incident rollback was confirmed by stream and runbook evidence.",
      "name": "MatrixArkAgent",
      "created_at_ms": 1781500004099
    }
  ],
  "scope": {
    "session_id": "agent-session-scale-1",
    "team": "infra_team",
    "project": "project_1"
  },
  "metadata": {
    "source": "ai_agent_feedback",
    "reply_to_context_pack_id": "pack-incident-54000"
  },
  "context_pack_id": "pack-incident-54000",
  "accepted_refs": [
    {"ref_type": "event", "ref_hash": 52000},
    {"ref_type": "resource_chunk", "ref_hash": 53000}
  ],
  "rejected_refs": []
}
```

If the caller sends only:

```json
{"messages": [{"role": "user", "content": "yes"}]}
```

MatrixArk should classify it as ambiguous or `NOISE`, not confirmation, unless
the current session has a previous ContextPack or assistant answer to attach it
to.

## Resource Envelope

Resources use the same message/scope/metadata shape, plus resource identity:

```json
{
  "messages": [
    {
      "role": "tool",
      "content": "Attached rollback runbook evidence for incident recovery.",
      "name": "resource_parser",
      "created_at_ms": 1781500003000
    }
  ],
  "scope": {
    "session_id": "agent-session-scale-1",
    "team": "infra_team",
    "project": "project_1"
  },
  "metadata": {
    "source": "ai_agent_resource",
    "node_path": ["company_a", "infra_team", "project_1", "resources", "scale_runbook.md"]
  },
  "raw_uri": "scale_runbook.md",
  "resource_type": "md"
}
```

TemporalStore stores parsed serving data and references. Raw bytes should stay
behind `raw_uri` unless a later resource pipeline explicitly copies them.

## MatrixArk Internal Mapping

```text
messages + scope + metadata
-> MatrixArk extraction and canonicalization
-> ContextNode path selection
-> ContextEvent with ingestion_time_ms as the primary timeline key
-> ContextEntity update when the event changes current state
-> ContextIndex rows for event_kind, entity, status, source, and event_time_bucket
-> ContextEmbedding for node/resource summaries
-> ContextSummary after async refresh
-> ContextCompressionEvent for old/cold windows
-> ContextPackAudit after retrieval
```

The mocked scale E2E validates this contract with:

```bash
python3 tools/run_context_pipeline_scale_e2e.py \
  --events-per-lane 5 \
  --write-results /tmp/context_pipeline_scale_e2e_agent.json
```

The generated corpus includes message, resource, and feedback envelopes. The
feedback case carries a prior context-pack reference so MatrixArk can classify a
short confirmation. The shared validator rejects malformed envelopes before the
C++ contract and Rust mock proxy execute the derived TemporalStore operations.
